# ProtoTool — 웹 프로토타입 툴

**브라우저에서 바로 도는 「쓰고 버리는 프로토타입」을 한 파일로 찍어 내고, 논 기록을 모아 주는 툴이다.**

빌드가 없다. 서버도 없다. 만들어 낸 것은 `index.html` 한 장이고, 더블클릭하면 열린다.

## 왜 있나

기획 절차의 **5단계(거친 프로토타입 묶음)와 6단계(몰아서 검증)** 를 받친다.

- 5단계는 「물음 하나 = 프로토타입 하나 = 답 하나」다. 프로토타입마다 뼈대를 다시 짜면 값이 붙으니
  **뼈대 한 장**을 툴이 준다.
- 6단계는 만들어 둔 여러 개를 한 자리에서 몰아서 본다. 그래서 **입구가 하나**(목록 페이지)여야 하고,
  논 기록이 **판정 기준에 댈 수 있는 숫자**로 나와야 한다.

절차 자체는 이 툴이 강제하지 않는다. 단계를 지키게 막는 것은 다른 툴의 몫이다.

## 게임 저장소와의 경계

**이 저장소에는 게임 낱말이 하나도 안 들어간다.** 어느 게임에 붙여도 그대로 돌아야 한다.

| 여기(ProtoTool) | 게임 저장소 |
| --- | --- |
| 뼈대 HTML · 틱 엔진 · 기록 조각 · 목록 생성기 | **프로토타입 본체** (`Prototypes/<날짜>-<이름>/index.html`) |
| 규약(폴더 모양 · `proto-meta` 형식 · 기록 JSON 칸 이름) | 물음 · 판정 기준 · 수치 · 논 결과(`결과.md`) |
| 툴 자신의 조사·설계·할 일 문서 | 기획 문서 · 판정 기록 · mem |

**만들어 낸 프로토타입과 기록 파일은 게임 저장소에 남는다.** 이 저장소에 게임의 프로토타입을 넣지 않는다.

## 폴더 구조

```
README.md
LICENSE
.gitignore
.claude/skills/proto-usage/SKILL.md   ← 쓰는 법 (지금은 뼈대)
Docs/
  Design/     ← 설계 문서
  Research/   ← 조사 문서
  Todo/할일.md ← 만들 부품 차례
```

**앞으로 생길 자리** (지금은 없다)

| 폴더 | 무엇이 들어가나 |
| --- | --- |
| `templates/` | 뼈대 HTML 한 장. 이걸 복사해서 프로토타입을 시작한다 |
| `lib/` | 틱 엔진 · 기록 · 내보내기 같은 **인라인용 조각**. 한 파일 규칙을 지키려고 붙여 넣는 재료다 |
| `scripts/` | 목록 페이지 생성기 · 기록 JSON 을 판정 표로 뽑는 스크립트 |

## 어디서 부르나 — 명령 두 벌

| 어디서 쓰나 | 명령 앞자리 |
| --- | --- |
| 스튜디오(Officina) 저장소에서 | `ProtoTool/scripts/…` · `ProtoTool/templates/…` |
| 게임 저장소에서 (서브모듈) | `Tools/ProtoTool/scripts/…` · `Tools/ProtoTool/templates/…` |
| ProtoTool 저장소 단독에서 | `scripts/…` · `templates/…` |

문서와 스킬의 예시는 **단독 저장소 기준**으로 적는다. 실제로 칠 때 위 표의 앞자리를 붙인다.

## `Prototypes/` 규약

프로토타입은 **게임 저장소**의 `Prototypes/` 아래 이렇게 둔다.

```
Prototypes/
  index.html              ← 목록 (툴이 만든다)
  protos.json             ← 목록의 재료. 각 프로토타입의 meta 를 모은 것
  2026-09-13-<이름>/
    index.html            ← 본체 한 파일 (CSS·JS 인라인)
    결과.md               ← 사용자가 논 뒤 한 줄씩
```

- **한 프로토타입은 한 파일이다.** 쪼개지 않는다. 한 걸음에 모든 자리에 닿는 것이 프로토타입의 속도다.
- **버릴 코드다.** 예쁘게 짜지 않고, 그림·소리·UI 를 다듬지 않는다.

본체 맨 위에 `proto-meta` 덩이를 둔다. 사람도 읽고 목록 생성기도 읽는다.

```html
<script type="application/json" id="proto-meta">
{ "물음": "결과가 확률로 갈릴 때 한 번 더 하고 싶어지나",
  "기준": ["멈추지 않고 5분", "다음에 뭐 하지 하고 멈춘 횟수 2회 이하", "한 판 더 생각이 든다"],
  "만든날": "2026-09-13" }
</script>
```

`결과.md` 는 사용자가 논 뒤에 손으로 쓴다. 기준 줄마다 통과/불통을 한 줄씩 적는다.

## 지금 상태

**뼈대만 있다.** 코드는 아직 하나도 없다. 1판 부품은 `Docs/Todo/할일.md` 를 본다.

## 만드는 차례

1. **① HTML 뼈대 한 장** — 모든 프로토타입이 여기서 시작한다.
2. **② 틱 엔진 + 빨리 감기** — 물음의 절반이 「시간」이다.
3. **③ 기록 + JSON 내보내기** — 안 재면 판정 기준을 못 채운다.
4. **④ 목록 페이지** — 몰아서 보려면 입구가 하나여야 한다.

1판 넷을 세 번 이상 쓴 뒤에 2판·나중 부품을 본다. **먼저 만들 이유가 없다.**

## 공개 저장소 검사

이 저장소는 공개다. 비밀값·개인정보·게임 낱말·남의 툴 이름이 들어가지 않게 `.claude/hooks/public_guard.py` 가 막는다.
받은 직후 한 번 `python .claude/hooks/public_guard.py --install` 을 친다 (git pre-commit 훅). 자세한 것은 `.claude/hooks/README.md`.

## 규칙

작업 규칙(`AGENTS.md` · `CLAUDE.md`)은 **이 저장소에 두지 않는다.**
스튜디오(Officina) 저장소나 붙어 있는 게임 저장소의 것을 따른다.
문서 문체와 자리 규칙도 그쪽 `doc-writing` 스킬을 본다.
