# ProtoTool 할 일

> 부품 목록과 공수 눈금은 게임 저장소의 가늠 문서 4장에서 옮겨 적었다.
> **공수는 전부 의견이다** — 실측하면 고친다.

## 1판 — 이것만 있으면 시작한다

| 순 | 부품 | 무엇을 하나 | 공수(의견) |
| --- | --- | --- | --- |
| ① | **HTML 뼈대 한 장** | 파일 하나에 `proto-meta` 덩이 · 수치 상수 덩이 · 화면 그리기 자리 · 기록이 미리 박힌 템플릿 | 2~3시간 |
| ② | **틱 엔진 + 빨리 감기** | 0.1초마다 도는 고리, ×1/×10/×60 버튼, 「N분 건너뛰기」 | 1~2시간 |
| ③ | **기록 + JSON 내보내기** | 클릭 수 · 버튼별 횟수 · 3초 이상 멈춤 · 총 논 시간을 모아 파일로 저장 | 1~2시간 |
| ④ | **목록 페이지** | 하위 폴더의 `proto-meta` 를 읽어 카드로 뿌린다 (제목 · 물음 · 기준 · 통과/불통) | 1~2시간 |

**1판 합계 눈금 5~9시간.** 프로토타입 하나 만드는 값과 비슷하다 —
이 선을 넘으면 툴이 게임을 잡아먹기 시작한 것이니 멈추고 다시 본다.

## 나중 — 세 번 아쉬우면 그때

| 순 | 부품 | 무엇을 하나 | 공수(의견) |
| --- | --- | --- | --- |
| ⑨ | 격자 캔버스 헬퍼 | 칸 격자 그리기 · 칸 누르기 · 끌어 옮기기 | 3~5시간 |
| ⑩ | 판정 표 출력 | 내보낸 기록 JSON 을 모아 「물음 / 기준 / 통과·불통」 마크다운 표로 | 1~2시간 |
| ⑪ | 저장 · 이어하기 | localStorage 에 상태를 두고 껐다 켜면 그동안의 시간을 준다 | 1~2시간 |
| ⑫ | Go CLI 승격 | `proto new / list / report` 로 툴킷 방식에 맞춘다 | 미정 |

- ⑨는 값이 제일 비싼데 답하는 물음은 둘뿐이다. **먼저 경제 시뮬 안에서 숫자로 대신 재 보고**,
  그래도 답이 안 나면 그때 만든다.
- ⑫는 1판 부품을 **세 번 이상 쓴 뒤에** 한다.

## 프로토타입 종류 넷 — 부품이 여기에 맞는지 본다

부품은 이 넷에서 거꾸로 뽑았다. 새 부품을 넣기 전에 「이 넷 중 몇이 쓰나」를 먼저 본다.

| 종류 | 화면 | 쓰는 부품 |
| --- | --- | --- |
| (가) 숫자만 도는 경제 시뮬 | 자원 숫자 줄 · 버튼 몇 개 · 상태 표 하나 | ①②③④ ⑤⑥⑧ |
| (나) 시간이 흐르는 방치 화면 | 진행 막대 여러 개 · 즉시 실행 버튼 · 빨리 감기 | ①②③④ ⑧⑪ |
| (다) 확률·뽑기 시뮬 | 표 · 「1회」·「1000회」 버튼 · 분포 표 · 격자 | ①③④ ⑤⑦⑧ |
| (라) 배치 격자 | 칸 목록 · 끌어 옮기기 | ①③④ ⑨ |

- (가)와 (나)는 **같은 틱 엔진**을 쓴다. 차이는 화면에 시계를 보여 주느냐다.
- (다)는 시간이 없어도 되고 **씨앗 난수**만 있으면 된다. 가장 싸다.
- (라)만 캔버스·끌기가 필요해 비싸다. 그래서 뒤로 미룬다.
